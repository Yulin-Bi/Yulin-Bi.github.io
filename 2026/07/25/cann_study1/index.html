CANN AutoFuse 基础（一）：专业术语基础总结

一、项目定位与内容范围

Graph-autofusion 是面向昇腾平台的算子与 Kernel 融合优化项目。本节集中说明项目涉及的基础数据结构、Host/Device 执行边界、昇腾 AI Core 的计算与存储单元，以及单个 Tile 在片上流水中的执行过程。

技术内容包括：

  1. Tensor、Shape、Rank、Stride、Tile、Tiling、Host、Kernel 等基础术语。
  2. GM、UB、MTE2、MTE3、Vector、Cube、AI Core 之间的数据与计算关系。
  3. TPipe、TQue、TBuf 对片上内存、缓冲槽和流水同步的抽象。
  4. 单个 Tile 从 GM 搬入 UB、完成计算并写回 GM 的执行过程。
  5. AutoFuse 与 SuperKernel 所处的不同优化层级。

Graph-autofusion 包含两条主要优化路线：

  • AutoFuse：重新分析融合图的轴、调度、Tiling 和片上内存，生成新的 Ascend C 融合 Kernel。
  • SuperKernel：组合已有子 Kernel，减少多次加载、下发和同步带来的调度开销。

二、基础名词

1. Host、Device 与 Runtime

名词 含义 在项目中的作用
Host 主机侧，通常是运行 Python/C++ 程序的 CPU 捕获/构造图、计算 Tiling、编译 Kernel、准备参数并发起 Kernel Launch
Device 设备侧，即昇腾 NPU 执行编译后的 Kernel，进行数据搬运和计算
Runtime 连接 Host 与 Device 的运行时软件 管理设备、Stream、内存、Kernel 加载和下发；项目依赖 CANN Runtime/ACL
Stream Device 任务的有序执行队列 同一 Stream 内的任务通常按依赖顺序执行，也可以使用多个 Stream 表达并发

Dimension 是某一个具体维度，例如 dim=0 表示 Batch 维，dim=1 表示 Channel 维。不同算子对维度含义的解释可能不同。

Batch

Batch 表示一次并行处理的样本数量。增大 Batch 通常能提高硬件利用率，但也会增加显存占用和单次计算量。

DType

DType 是数据类型，例如 float32、float16、bfloat16、int32、bool。数据类型影响：

  • 每个元素占用的字节数；
  • UB 中一次能放多少元素；
  • Vector/Cube 指令是否支持；
  • 计算速度、精度和对齐要求。

Layout、Stride

Layout 是 Tensor 的数据排布方式，例如 NCHW、NHWC、ND、NZ。

Stride 描述某个维度的索引增加 1 时，实际内存地址跨过多少元素。例如连续的 [B, M, N] Tensor，其 stride 通常近似为：

4. Tile、Tiling、Block

Tile

完整 Tensor 往往无法一次放进片上存储，因此要切成小块，每个小块就是 Tile。

例如长度为 4096 的向量，每次在 UB 中处理 512 个元素：

Tiling

Tiling 是确定如何切块的过程，包括：

  • 沿哪一根轴切；
  • 每块大小是多少；
  • 每个核处理哪些块；
  • Reduce 轴怎样分块；
  • 是否需要尾块处理；
  • 是否使用 Double Buffer；
  • 是否需要多个候选方案。

Shape 描述“完整问题有多大”，Tiling 描述“怎样把完整问题拆成硬件能高效处理的小任务”。

Double Buffer 并不保证性能提升。它把同类 Queue 的缓冲槽从一份增加到两份或多份，以便不同 Tile 的 CopyIn、Compute 和 CopyOut 重叠，但也会增加 UB 占用。

UB 占用增加本身不必然直接增加执行时间；当它压缩了 TBuf、中间 Tensor 或其他 Queue 的可用空间，并迫使 Tile 变小时，会产生以下间接代价：

  • Tile 数量和外层循环次数增加；
  • DataCopy、EnQue/DeQue 和尾块处理次数增加；
  • 单次搬运变小，带宽利用率可能下降；
  • 融合图的其他中间结果可能无法继续留在 UB；
  • 某些候选 Schedule 可能因 UB 不足而被淘汰。

因此，Double Buffer 应作为 Tiling/Schedule 候选策略进行比较，而不是默认开启。是否启用取决于 Shape、DType、Tile 大小、融合图的临时 Buffer、SoC 的 UB 容量以及 MTE/Vector 各阶段耗时。

场景 Double Buffer 倾向
CopyIn/Compute/CopyOut 耗时接近，且 UB 充足 开启后可能通过流水重叠降低耗时
Compute 明显占主导，MTE 等待很少 重叠收益有限
Shape 很小、Tile 数量少 初始化和队列管理开销可能无法摊薄
UB 紧张，开启后必须显著减小 Tile 可能增加总耗时，应优先比较关闭方案

最终应在相同输入和运行条件下比较开启/关闭方案的 Kernel 总耗时，并结合 UB 占用、Tile Size/Tile Num、MTE2/MTE3 时间和 Vector 时间确定选择。

三、昇腾硬件和存储单元

不同昇腾 SoC 的物理组织、单元数量和能力存在差异，本节按照项目代码采用的逻辑抽象进行说明。

1. AI Core、AIC、AIV

名词 作用
AI Core/AICore 昇腾 Device 上执行算子 Kernel 的主要计算核心统称
AIC 偏 Cube/矩阵计算的执行核心或 Kernel 侧
AIV 偏 Vector/向量计算的执行核心或 Kernel 侧
Mix Kernel 同时使用 Cube 和 Vector 计算能力的 Kernel

项目中会区分 AIC-only、AIV-only、Mix 等 Kernel 类型。具体物理核比例随 SoC 不同，不能把某个型号的数量当作所有昇腾卡的固定规则。

2. GM 与 UB

GM：Global Memory

GM 是 Device 全局内存，通常对应 HBM/DDR 一类容量较大的外部存储。

特点：

  • 容量大；
  • 所有核可以访问；
  • 相比片上存储访问延迟更高、带宽更宝贵；
  • Kernel 输入、输出通常位于 GM。

UB：Unified Buffer

UB 是靠近计算单元的片上高速存储，Ascend C 中常通过 LocalTensor 使用。

特点：

  • 容量远小于 GM；
  • 延迟低、适合 Vector 计算；
  • 通常需要显式规划和复用；
  • Tile 大小必须受 UB 容量限制。

AutoFuse 的核心目标之一，就是让中间结果尽量留在 UB 中，而不是每经过一个算子就写回 GM。

3. MTE2 与 MTE3

MTE 是 AI Core 数据通路中的搬运引擎。

单元 在常见 Vector 数据流中的主要方向
MTE2 将输入数据从 GM 搬到 UB，即 CopyIn
MTE3 将输出数据从 UB 搬回 GM，即 CopyOut

TBuf 是一块直接使用的片上 Buffer，通常位于 TPosition::VECCALC：

它一般用于：

  • Reduce 的临时累加结果；
  • Broadcast、Transpose 的工作空间；

  • 只在 Compute 阶段内部使用的局部数据。

获取方式 AllocTensor、DeQue Get()
状态操作 EnQue、DeQue、FreeTensor 通常没有队列状态操作

Double Buffer 常见 通常不作为队列式双缓冲使用

6. 片上存储补充

存储 技术作用
L1 Cube 数据进入更底层计算缓冲区前的片上缓存/暂存空间
L0A/L0B Cube 计算的左右输入矩阵缓冲区
L0C Cube 计算结果/累加缓冲区
UB Vector 侧主要片上数据和临时结果存储
L2 多个核共享的较大缓存层，位于 AI Core 与 GM 之间
GM Device 全局内存

AutoFuse 的 Vector 数据通路主要表现为 GM → UB → Vector → UB → GM。

职责边界：

  • TQue/TBuf 管理的是片上内存和生命周期，本身不是计算单元。
  • EnQue/DeQue 表达就绪与消费关系，本身不是数据搬运。
  • DataCopy 才对应实际搬运；Add/Abs/Reduce 等 API 才对应实际计算。
  • Double Buffer 的价值是让不同 Tile 的搬入、计算和搬出尽量重叠。

轴选择、Tile Split、Block Split、分核和 Reduce 模板选择属于建立在该数据通路之上的调度机制。

五、基础技术要点

  1. Host 负责构图、编译、Tiling 和下发，Device 负责执行 Kernel。
  2. Tensor 由 Shape、Rank、DType、Layout 和 Stride 描述；Stride 决定坐标怎样映射到内存地址。
  3. 完整数据通常位于 GM，Tile 通过 MTE2 搬入 UB，经 Vector/Cube 计算后再由 MTE3 写回 GM。
  4. Tiling 决定切块、分核、尾块和片上资源使用方式，TilingData 将 Host 决策传给 Kernel。
  5. TPipe 管理 Kernel 的片上 Queue/Buffer；TQue 负责流水交接与缓冲槽复用；TBuf 负责计算阶段临时空间。
  6. TQue 的 AllocTensor/EnQue/DeQue/FreeTensor 是生命周期与同步操作，DataCopy 才是真正搬运。
  7. AutoFuse 重新生成融合 Kernel，重点减少中间 GM 搬运；SuperKernel 组合已有 Kernel，重点减少下发与同步开销。
  8. 轴分类、融合判定、Schedule 和 Reduce 模板构成 AutoFuse 的上层调度机制，不属于基础数据通路本身。
